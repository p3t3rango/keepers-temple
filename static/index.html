Settings

Personas

A persona is an AI identity you can switch into per chat — like "code-reviewer", "journal-companion", "brainstorm-partner". Each persona's identity text replaces Layer 0 below when active. Switch via the topbar; the default persona uses the Layer 0 identity edited below.

Identity (Layer 0)

A persistent system prompt loaded into every conversation, no matter the wing. Stored in ~/.mempalace/identity.txt. Describe who the AI is and who you are — not what you're working on. Project / topic context belongs in the per-wing system prompt under Conversation.

Backups

Snapshot your palace (drawers + knowledge graph + pending review) to ~/.mempalace/backups/. Use before a bulk import or a nuke so you can roll back if anything goes wrong.

Voice output (macOS speech)

The assistant's responses can be spoken aloud using macOS's built-in speech synthesizer (the same engine as say). Zero install, fully local, instant. Pick any installed system voice. Tip: the default voices (Samantha, Daniel) sound robotic. For dramatically more natural-sounding speech, install a Premium voice in System Settings → Accessibility → Spoken Content → System Voice → Manage Voices… Look for any voice tagged (Premium) — Zoe, Evan, Karen, Tom are particularly good. After install, refresh this app and the new voice appears in the picker below. Use the stop button (■ in the composer) or Esc to halt mid-reading.

Voice input (Whisper)

Click the mic in the composer to dictate. Whisper runs locally on Apple Silicon — nothing leaves your Mac. First use of each model size downloads it once.

Permanent wing files

Installed Ollama models

Manage Ollama models without leaving the app. Sizes are on disk; pulling a new model downloads to ~/.ollama/models.

Pull a new model

Browse the catalog at ollama.com/library for tag names. Common pattern: name:tag e.g. llama4:scout, qwen3.6:35b-a3b-q4_K_M. Large pulls take minutes.

Sub-agents

Specialists the primary chat agent can delegate subtasks to. Each agent has its own system prompt, model, and optional wing for memory scope. When tools are enabled in chat, the model gets a delegate(agent, task) tool listing every agent below. Sub-agents do not have delegate themselves (no recursion).

How delegation feels

A typical use: you have a "researcher" agent on a small fast model and a "synthesizer" agent on a big reasoning model. The primary agent delegates the lookup to researcher, then hands the findings to synthesizer for the final answer. Each delegate call shows up as a tool-call chip in the assistant bubble — click to expand and see what was asked + what came back.

External MCP servers

Connect to other Model Context Protocol servers (filesystem, github, jira, postgres, etc.) so the agent can use their tools alongside ours. Tools enabled in any chat will appear as mcp__<server>__<tool>. Enabled servers are spawned lazily on first chat and reused.

Quick examples

Most official MCP servers run via npx (Node) or uvx (Python). You'll need Node and/or uv installed.
  • Filesystem: npx -y @modelcontextprotocol/server-filesystem ~/Documents
  • GitHub: npx -y @modelcontextprotocol/server-github + GITHUB_TOKEN env
  • Postgres: npx -y @modelcontextprotocol/server-postgres postgresql://...
  • Browser: npx -y @modelcontextprotocol/server-puppeteer
Browse the full catalog at github.com/modelcontextprotocol/servers.

Wings & rooms — how to think about them

                
    
                  
  • Wing = a top-level domain. A project, a person, or a big topic. Examples: personal, dos-clone, health, work.
    • 
                  
  • Room = a facet inside a wing. For a project: auth, gameplay, billing. For a person: conversations, preferences.
    • 
                  
  • Auto-extracted facts land in rooms named hall_<type> (e.g. hall_preferences) inside the active wing.
    • 
                  
  • Memory recall is scoped to the current wing so unrelated context can't bleed in.
